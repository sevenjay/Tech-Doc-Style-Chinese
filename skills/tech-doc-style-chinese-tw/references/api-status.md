# API 狀態

僅在撰寫、翻譯或審閱 API 文件、狀態標籤、錯誤碼和 API 提示時讀取本檔案。

## 基本原則

- 先確認狀態在此 API 中的實際含義，再選擇中文。
- 不把一個英文狀態詞固定對應為唯一中文。
- 保持 HTTP 狀態、業務狀態、任務狀態和 API 提示之間的區別。
- 錯誤文案儘量說明問題、影響和復原方式。
- 不修改狀態碼、列舉值、欄位名稱和回應原文。

## 常見狀態詞

- `Success`
  - 根據語義使用 `已完成`、`已處理`、`請求成功`
- `Invalid`
  - 使用 `無效`、`格式有誤`、`驗證失敗`
  - 不預設翻譯成 `非法`
- `Available`
  - 使用 `已啟用`、`可取得`、`可存取`、`可使用`
- `Unsupported`
  - 使用 `暫不支援`、`不支援該類型`、`目前不支援`
- `Pending`
  - 使用 `待處理`、`處理中`、`待確認`
- `Expired`
  - 使用 `已過期`
- `Missing`
  - 使用 `缺少`、`未提供`
- `Denied`
  - 使用 `被拒絕`、`未通過`
- `Forbidden`
  - 根據語義使用 `無權限存取`、`目前不允許存取`
- `Not Found`
  - 使用 `找不到對應內容`、`找不到對應資料`
- `Accepted`
  - 使用 `已受理`、`已接收，等待處理`
- `Completed`
  - 使用 `已完成`
- `Failed`
  - 使用 `失敗`、`處理失敗`
- `Conflict`
  - 使用 `狀態衝突`、`資源狀態不一致`、`請求與目前狀態衝突`
- `Unauthorized`
  - 根據實際原因使用 `未登入`、`身分驗證失敗`、`缺少身分驗證資訊`
  - 不機械翻譯成 `未授權`
- `Bad Request`
  - 使用 `請求參數有誤`、`請求格式有誤`
- `Timeout`
  - 使用 `請求逾時`、`處理逾時`

## 參數說明

每個參數應儘量說明：

- 資料型別和格式
- 是否必填
- 單位
- 預設值
- 允許值或範圍
- 省略參數時的行為
- 與其他參數的相依或互斥關係

不要用「正常值」「根據情況填寫」「相關資訊」等無法執行的說明。
